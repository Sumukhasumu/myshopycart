DESIGN / ARCHITECTURE PATTERNS

Patterns behind the implementation

Key architectural and engineering patterns used in MYSHOPYCART to organize services, handle failures, manage data and maintain reliable API behavior.

01

Microservices Architecture

API Gateway for centralized routing, Eureka for service discovery and Spring Cloud Config for centralized configuration. Database per Service and Polyglot Persistence use PostgreSQL and MongoDB. Messaging supports event-driven integration.

Gateway · Eureka · Config · Messaging
02

Resilience Patterns

Circuit Breaker protects payment workflows from repeated failures. Retry handles configured transient failures, while TimeLimiter enforces a payment gateway timeout.

Resilience4j · Retry · TimeLimiter
03

Distributed Caching

Redis caching in Product Service reduces repeated data retrieval. Cache eviction keeps cached product information aligned with relevant update and delete operations.

Redis · Cacheable · CacheEvict
04

Idempotency

Payment idempotency-key validation helps prevent duplicate processing when the same payment request is submitted again.

Payment · Idempotency Key
05

Global Exception Handling

Centralized REST exception handling with @RestControllerAdvice, custom business exceptions, request validation and handling of payment-related failures.

Spring · ExceptionHandler · Validation
06

Service Mesh

Service Mesh is a possible future enhancement for service-to-service traffic management, observability and security. It is not currently configured as part of MYSHOPYCART.

Future enhancement

These patterns describe the implementation areas identified in the project. Saga, CQRS and Service Mesh are not presented as implemented features.
