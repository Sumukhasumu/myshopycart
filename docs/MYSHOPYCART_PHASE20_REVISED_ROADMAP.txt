2. PHASE 20 OBJECTIVES
==================================================

Phase 20 has two related tracks.

TRACK A — LOCAL KUBERNETES LEARNING

1. Understand Kubernetes architecture and deployment.
2. Inspect the existing application and Docker configuration.
3. Choose a suitable local Kubernetes environment for an 8 GB RAM laptop.
4. Create and validate Kubernetes manifests.
5. Configure Namespace, Deployment and Service resources.
6. Configure ConfigMaps and secure Secret handling.
7. Configure Ingress where appropriate.
8. Configure readiness and liveness probes.
9. Configure resource requests and limits.
10. Understand internal service communication and DNS.
11. Decide how databases and messaging dependencies will be provided.
12. Evaluate optional Horizontal Pod Autoscaler (HPA).
13. Validate deployment and practice troubleshooting.
14. Document local deployment commands and results.

TRACK B — GOOGLE CLOUD DEPLOYMENT

1. Inspect the actual application architecture and dependencies.
2. Evaluate Google Kubernetes Engine (GKE) as a serious option.
3. Calculate the total expected cost of running the required application on GKE.
4. Proceed with GKE only if the complete required deployment is verified to fit a zero-cost plan and the user approves it.
5. If GKE cannot meet the zero-cost requirement, keep Kubernetes learning local.
6. Evaluate Cloud Run as an alternative for public hosting.
7. Check how databases, Redis, Kafka and RabbitMQ will be provided.
8. Verify free-tier eligibility, pricing, billing requirements and regional availability.
9. Deploy publicly only after architecture and cost approval.
10. Document actual results, limitations, cost assumptions and cleanup instructions.

CLOUD DECISION RULE

GKE provides a monthly credit for eligible cluster-management fees. That credit does not automatically cover compute, networking, databases, storage, load balancing, messaging or all other resources.

Therefore:

- Do not interpret the GKE cluster credit as proof that the entire application can run for free.
- Calculate the cost of the actual services and dependencies required by MYSHOPYCART.
- Consider current free-tier eligibility and any temporary promotional credits separately.
- Do not count temporary credits as a permanent zero-cost solution.
- Proceed with cloud GKE only if the required deployment has a verified zero-cost path within the applicable limits.
- If GKE is not fully free, use local Kubernetes for learning and evaluate Cloud Run for public hosting.
- Cloud Run also requires a cost check, including supporting databases and messaging dependencies.
- If neither cloud option meets the user's budget, keep the application local until an affordable hosting plan is approved.

The objective is to gain Kubernetes skills and, if feasible, host MYSHOPYCART publicly without unexpected charges.
